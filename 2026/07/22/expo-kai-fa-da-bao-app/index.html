expo开发打包APP

Expo React Native Android GitHub Actions CI/CD
前端开发
发布日期:   2026-07-22

在 React Native / Expo 开发中，将项目打包成 Android APK 安装包是发布前的关键一步。然而，许多开发者在打包时经常面临环境配置复杂、云端排队时间长等痛点。

本文将详细对比并介绍 Expo 打包 APP 的三种主流方案：EAS 官方云打包、本地命令行/Docker 打包 以及 基于 GitHub Actions 的免费自动化构建方案，帮助你选择最适合自己的打包工作流。

方案一：Expo EAS 官方云打包

Expo 官方提供了 EAS (Expo Application Services) 云构建服务，它可以在云端为我们配置好所有的 Android/iOS 编译环境，并生成安装包。

⚠️ EAS 云打包的劣势

  • 排队时间极长：在 Expo 免费层级下，云端构建服务器资源有限，高峰期排队常常需要半小时甚至一小时以上。
  • 额度限制：免费账号每月有打包次数上限。
  • 代码安全：需要将项目代码上传至 Expo 平台，对部分敏感项目可能存在安全考量。

方案二：本地环境打包 (Local Build)

为了避开云端排队，可以使用本地物理机进行打包。

⚠️ 本地打包的劣势

  • 环境占用巨大：Android SDK、NDK、Gradle 缓存以及 Docker 镜像总共会占用几十个 G 的磁盘空间。
  • 本地资源消耗高：编译 Android 原生代码时，CPU 和内存会被占满，导致电脑卡顿。
  • 配置繁琐：JDK、Android SDK 路径以及系统环境变量（如 ANDROID_HOME）的配置极易出错。

方案三：GitHub Actions 自动化打包 (黄金方案 ✨)

结合前两者的优点，我们可以利用 GitHub 提供的免费 CI/CD 算力。通过配置 GitHub Actions，在云端虚拟主机上自动完成 Expo Prebuild 和 Android 编译，最终将打包好的 APK 自动发布到 GitHub Release 中。

  1. 推送代码与 Tag：
    将代码提交并推送至您的 GitHub 仓库（例如 your-app-repo）。如果要发布正式版，可以推送一个版本号 Tag：
  2. 网页端手动触发：
    进入您的 GitHub 仓库页面，点击 Actions -> Build Android APK -> Run workflow 手动触发构建。
  3. 下载 APK：
    构建流程执行完毕（约需 5 分钟），页面右侧的 Releases 栏中会自动生成一个新的发布记录，直接点击下载附件中的 app-release.apk 即可！

💡 方案对比与总结

维度 EAS 官方云打包 本地 Docker / 物理机打包 GitHub Actions 自动化打包 (推荐)
费用 免费（有次数与额度限制） 完全免费 完全免费（个人公有仓库免费使用）
构建速度 极慢（需要排队 20-60 分钟） 较快（视电脑配置而定，约 5-10 分钟） 极快（无排队，约 5 分钟）
环境依赖 无需配置本地环境 本地需配置繁重的 SDK/NDK/Docker 无需配置本地环境，免去配置痛苦
电脑负担 无负载 极高（CPU、内存满载，发热卡顿） 无负载，全部由 GitHub 虚拟机运行
代码安全 需上传至 Expo 平台 代码仅保留在本地 保存在您自己的 GitHub 仓库中

综上所述，基于 GitHub Actions 的打包方案 在不消耗本地硬件资源、不配置复杂环境的前提下，实现了极速、免费且全自动的编译。强烈建议将该工作流作为 Expo 项目开发的标配方案！
